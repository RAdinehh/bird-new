# بخش ۷ — Empty / Loading / Error

## E1 — Empty State

**چیست:** وقتی لیست خالی است (چه بدون فیلتر، چه با فیلتر).

**مرجع:** NN/g — «Empty states»

**کد:** `src/shr/components/ui/Card.tsx` — `Empty`

**قاعده:**
- آیکون + عنوان + توضیح یک‌خطی + دکمه اقدام
- **بدون فیلتر:** «اولین [X] را بسازید» + دکمه ساخت
- **با فیلتر فعال:** «فیلترها را پاک کنید» + دکمه پاک کردن
- تعداد فیلتر فعال در badge نمایش داده شود

**نمونه بد:** «نتیجه‌ای یافت نشد» بدون دکمه → کاربر گیر می‌کند.

**چک:**
~~~bash
grep -rn "<Empty" src/mod/ --include="*.tsx" | wc -l
~~~

---

## E2 — Loading

**چیست:** حالت بارگذاری.

**مرجع:** MD3 — «Progress indicators»

**قاعده:**
- **لیست/جدول:** Skeleton (نه spinner) — مثل Stripe، LinkedIn
- **عملیات کوتاه (<۱s):** Spinner
- **عملیات طولانی (>۳s):** Progress bar با درصد
- **هرگز:** صفحه خالی سفید در حین بارگذاری

**نمونه بد:** spinner وسط صفحه خالی → کاربر نمی‌داند چه چیزی در حال بارگذاری است.

**چک:**
~~~bash
grep -rn "Skeleton\|skeleton\|Spinner\|spinner" src/shr/components/ui/
~~~

---

## E3 — Error

**چیست:** خطا در بارگذاری یا عملیات.

**مرجع:** NN/g — «Error messages»

**قاعده:**
- پیام دقیق: **«چه چیزی شکست + چه کار کن»**
- دکمه «تلاش مجدد» اگر قابل بازگشت
- لاگ در console با prefix `[moduleName]`
- رنگ `--danger`
- آیکون هشدار

**نمونه بد:** «خطا رخ داد» → بی‌فایده.

**نمونه خوب:** «ذخیره‌ی گله شکست خورد. اتصال اینترنت را چک کنید و دوباره تلاش کنید.» + دکمه تلاش مجدد.

**چک:**
~~~bash
grep -rn "ErrorBox\|ErrorState\|showToast.*error" src/shr/components/ src/cor/store/
~~~

## A3 — Labels & Alt

**قاعده:**

# بخش ۱۱ — Animation (انیمیشن)

## An1 — Timing & Easing

**مرجع:** MD3 — «Motion»

**قاعده:**
- **مدت:** ۱۵۰–۳۰۰ms برای transitions کوچک، ۳۰۰–۵۰۰ms برای بزرگ
- **Easing:**
  - ورود: `ease-out`
  - خروج: `ease-in`
  - تاکید: `cubic-bezier(.4, 0, .2, 1)`
- **کاهش حرکت:** `prefers-reduced-motion: reduce` → انیمیشن‌ها غیرفعال یا کوتاه‌تر
- **بدون انیمیشن اجباری** — هر انیمیشن باید هدف داشته باشد

**نمونه بد:** انیمیشن ۲ ثانیه‌ای برای باز شدن Modal → کاربر معطل می‌شود.

# بخش ۱۲ — Colors & Semantic

## C1 — رنگ‌های معنایی

**قاعده:** رنگ باید **معنا** داشته باشد، نه سلیقه.

| نقش | توکن | استفاده |
|---|---|---|
| **accent** | `--accent` | دکمه primary، لینک |
| **danger** | `--danger` | حذف، خطا، هشدار جدی |
| **warn** | `--warn` | هشدار غیرجدی، انقضا نزدیک |
| **success** | `--success` | تأیید، موفقیت |
| **info** | `--info` | اطلاع‌رسانی |
| **muted** | `--muted` | متن ثانویه، hint |
| **dim** | `--dim` | placeholder، غیرفعال |

**قاعده:**
- یک رنگ نباید دو معنا داشته باشد
- `--danger` فقط برای حذف/خطا — نه برای تزئین
- رنگ‌ها از CSS variables — نه hardcode

**چک:**
~~~bash
grep -rn "#[0-9a-fA-F]\{3,6\}" src/ --include="*.tsx" | grep -v "var(--" | wc -l
~~~
🔻 ratchet. هدف: صفر hardcoded.

**مرجع:** MD3 — «Buttons»، Atlassian Design System

**کد:** `src/shr/components/ui/Btn.tsx` (قفل‌شده)

| Variant | استفاده | رنگ |
|---|---|---|
| `primary` | عمل اصلی صفحه | `--accent` |
| `secondary` | عمل ثانویه | `--card` + border |

**نمونه بد:** دو دکمه primary کنار هم → کاربر گیج می‌شود.
