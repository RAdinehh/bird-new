## 🎨 ۱) قوانین Placeholder (۱-۷)

| # | دستور |
|---|---|
| ۱ | همیشه **فارسی** — بدون لغت لاتین |
| ۲ | **کوتاه** — نباید overflow کنه |
| ۳ | **بدون تکرار label** — «نام سالن» → «شمالی» (نه «نام سالن») |
| ۴ | **بدون «مثلاً:»** — خود placeholder نمونه‌ست |
| ۵ | فیلد عددی → نمونه عددی («۱۰»، «۵» نه «مثلاً ۱۰») |
| ۶ | کد فنی → `dir="ltr"` مجاز |
| ۷ | محو با تایپ (پیش‌فرض HTML) |

---

## ⭐ ۲) قوانین Required Fields (۸-۱۱)

| # | دستور |
|---|---|
| ۸ | فقط فیلدهای **حیاتی** اجباری شن (نه همه) |
| ۹ | سالن: نام، طول، عرض، ارتفاع، پرنده، نژاد |
| ۱۰ | دما و رطوبت **آزاد** (auto-fill می‌شن) |
| ۱۱ | ستاره قرمز **ضخیم** — `fontWeight: 700`, `fontSize: 1.2em` |

---

## 🚨 ۳) قوانین Error Display (۱۲-۱۷)

| # | دستور |
|---|---|
| ۱۲ | خطا **فقط بعد از کلیک «ذخیره»** ظاهر شه — نه دائمی |
| ۱۳ | الگو: `saveAttempted` state (false → true در save، ریست در openNew/openEdit) |
| ۱۴ | با تایپ کاربر **پاک شه** — `onErrorClear` |
| ۱۵ | چینش **راست‌چین** یکنواخت — `dir="rtl"` + `textAlign: right` |
| ۱۶ | **بدون آیکون ایموجی** (⚠️/💡 حذف شدن) — فقط متن رنگی |
| ۱۷ | دکمه «ذخیره» **فعال** بمونه (نه disabled) — با کلیک، خطا نشون بده |

## 🎯 ۴) پیام خطای پویا (۱۸-۲۲)

| # | دستور |
|---|---|
| ۱۸ | **هر فیلد، پیام خودش** — نه پیام عمومی |
| ۱۹ | طول خالی → «لطفاً **طول** را وارد کنید» |
| ۲۰ | عرض خالی → «لطفاً **عرض** را وارد کنید» |
| ۲۱ | ارتفاع خالی → «لطفاً **ارتفاع** را وارد کنید» |
| ۲۲ | الگو: `requiredFloatRange(label, min, max)` با `required_error` پویا |

---

## ✨ ۵) قوانین Auto-fill (۲۳-۳۰)

| # | دستور |
|---|---|
| ۲۳ | فقط **بعد از انتخاب نژاد** فعال شه |
| ۲۴ | تمام اعداد **فارسی** — `toFa` |
| ۲۵ | **Override کاربر** اولویت داره — `autoFields` |
| ۲۶ | `capacity` = `area × densityMax` |
| ۲۷ | `temp/humidity/light` = `env[0]` |
| ۲۸ | `litterType` = `litter.recommended[0]` + نگاشت |
| ۲۹ | `feederType` = `equipment.feeder` |
| ۳۰ | `drinkerType` = `equipment.drinker` |

## 🔗 ۶) قوانین Sync — Single Source (۳۱-۳۵)

| # | دستور |
|---|---|
| ۳۱ | گروه «⚙️ سیستم‌ها» از فرم سالن **حذف شه** |
| ۳۲ | `ventilationSystem`, `feederType`, `drinkerType`, `litterType` **فقط از تجهیزات** |
| ۳۳ | `ventilation` و `light` (عددی) هم **از تجهیزات** |
| ۳۴ | `computeHallPatch` در `store.ts` — هر `addEquip/updateEquip/deleteEquip` sync کنه |
| ۳۵ | فیلتر با **`type` یا `category`** (نه فقط `type`) |

## 📐 ۷) قوانین Layout (۳۶-۴۱)

| # | دستور |
|---|---|
| ۳۶ | **دو ستونه (Grid2/RowGrid)** برای فیلدهای کوتاه: عدد، تاریخ، لینک، percent |
| ۳۷ | **تک‌ستونه (Row)** برای فیلدهای بلند: متن، لیست، آدرس، یادداشت |
| ۳۸ | `alignItems: 'start'` برای Grid2 (هم‌ترازی از بالا) |
| ۳۹ | **label مخفی** (`visibility: 'hidden'`) برای هم‌ترازی کادر محاسبه با input |
| ۴۰ | `RowWithStatus` با hint **توی Grid2 نذار** → بهم می‌ریزه |
| ۴۱ | همه RTL — فقط کد فنی LTR |

## 📊 ۸) کارت‌های KPI (۴۲-۴۶)

| # | دستور |
|---|---|
| ۴۲ | کارت‌های KPI **دو ستونه** (نه تک‌خطی) |
| ۴۳ | ساختار: **آیکون + label + emoji** (هدر) → **نوار پیشرفت** → **درصد + تعداد** (footer) |
| ۴۴ | رنگ‌بندی: 🟢 ok / 🟡 low / 🔴 very-low / 🟣 over / ⚪ none |
| ۴۵ | `pct > 100` → نمایش **ضریب** («۶.۷×») نه درصد («۶۷۰٪») |
| ۴۶ | `minHeight: 80` برای کارت‌ها |

## 🖼 ۹) مدال جزئیات (۴۷-۵۰)

| # | دستور |
|---|---|
| ۴۷ | هدر مدال: **آیکون + نام دسته + emoji وضعیت** |
| ۴۸ | **نوار پیشرفت** با متن «X از Y — درصد» |
| ۴۹ | **پیام وضعیت**: ✅ کافی / 🟡 کم / 🔴 نیاز فوری / 🟣 اضافه |
| ۵۰ | لیست تجهیزات: **آیکون + نام + تعداد + ظرفیت** + دکمه ویرایش/حذف |

## 🌾 ۱۰) استانداردهای تجهیزات (۵۱-۵۷)

| # | دستور |
|---|---|
| ۵۱ | واحد **«عدد»** برای تجهیزات شمارشی (کله‌قندی، سطل، بشقابی) |
| ۵۲ | واحد **«راس»** برای ظرفیت (تعداد پرنده) |
| ۵۳ | کله‌قندی ۳ لیتری → **۶۰-۸۰ پرنده** |
| ۵۴ | سطل لبه‌دار ۱۰ kg → **۵۰-۷۰ پرنده** |
| ۵۵ | بشقابی → **۶۰-۸۵ پرنده** (قطر ۳۵-۴۸ cm) |
| ۵۶ | نیپل → **۸-۱۲ پرنده** |
| ۵۷ | `stdKey` **غلط رو حذف کن** — `fanM3PerKg` (نسبت) ≠ ظرفیت یک فن |

## 🐛 ۱۳) روش کشف باگ پنهان (۶۵-۷۰)

| # | دستور |
|---|---|
| ۶۵ | **قبل از fix، grep کن** — `AI-RULES ب۲` |
| ۶۶ | `git status --short` به جای `git status -s` (توی Termux فرق داره) |
| ۶۷ | `cat -A` برای دیدن whitespace دقیق |
| ۶۸ | اگه tsc خطا داد → **rollback، نه fix** |
| ۶۹ | anchor های چندخطی → **روش خط‌به‌خط** (نه regex) |
| ۷۰ | کد فنی → **همیشه فایل واقعی رو ببین** |

## 📌 نحوه استفاده

قبل از هر کار روی ماژول جدید (flk، dlg، fed، egg، ...) این ۷۰ دستور رو مرور کن.

**اولویت‌بندی کاربردی:**

1. **دستورات ۶۵-۷۰** (روش کار) — قبل از هر تغییر
2. **دستورات ۱۲-۲۲** (Error + پیام پویا) — مهم‌ترین UX
3. **دستورات ۳۱-۳۵** (Sync + Single Source) — جلوگیری از باگ
4. **دستورات ۳۶-۴۱** (Layout) — یکدستی بصری
5. **دستورات ۱-۱۱** (Placeholder + Required) — ظاهر فرم
6. **دستورات ۴۲-۶۱** (KPI + مدال + استاندارد) — تجهیزات
7. **دستورات ۶۲-۶۴** (Legacy) — تمیزکاری
