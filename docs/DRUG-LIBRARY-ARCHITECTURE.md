# DRUG-LIBRARY-ARCHITECTURE.md

> هدف: طراحی یک کتابخانه جامع و استاندارد برای داروهای شیمیایی و گیاهی طیور.
> وضعیت: در انتظار شروع (جلسه بعد)

## 📍 ۱. جایگاه در کد (معماری)
- `src/shr/drugs/vet/library.ts`: ماتریس داروهای شیمیایی.
- `src/shr/drugs/herbal/library.ts`: ماتریس داروهای گیاهی.
- `src/shr/drugs/contracts.ts`: قرارداد مشترک (Interface) برای هر دو.
- **چرا shr؟** چون مصرف‌کننده‌های متعدد دارد (whs, dlg, rep, dsh) و یک داده مرجع جهانی است.

## 🧠 ۲. منطق داده (ماتریس دوز)
هر دارو می‌تواند برای گونه‌های مختلف (`broiler`, `layer`, `breeder`, `turkey`, `duck`)، روش‌های مختلف (`water`, `feed`, `injection`, `topical` یا روش‌های سنتی) و دوزهای مختلف استفاده شود.
- **داده‌ها باید به صورت آرایه‌ای از دوزها باشند**، نه فیلدهای ساده `dosePerBird` و `dosePerLiter`.

## 🔌 ۳. ماژول‌های مصرف‌کننده
- **انبار (whs)**: هنگام تعریف آیتم دارو، از کتابخانه انتخاب کند.
- **فرم روزانه (dlg)**: دوز را بر اساس species و route خودکار پر کند.
- **گزارش (rep)**: تحلیل مصرف بر اساس دوز استاندارد.
- **داشبورد (dsh)**: نمایش آمار دقیق.

## 🌿 ۴. تفکیک شیمیایی و گیاهی
- **شیمیایی**: تمرکز بر دوره پرهیز (withdrawal)، تداخل دارویی، دوز دقیق mg/kg.
- **گیاهی**: تمرکز بر طبع، شکل دارو (طبیخ، سفوف)، روش‌های سنتی.
- هر دو از یک `contract` واحد پیروی می‌کنند تا `calculateHealthDose` بتواند هر دو را پردازش کند.

## 🚀 ۵. سطوح قابلیت‌ها
1. **پایه**: ماتریس دوز (species × route × dose).
2. **حرفه‌ای**: هشدار تداخل دارویی، حداکثر دوز روزانه.
3. **پیشرفته**: پیشنهاد بر اساس سن، ردیابی مقاومت دارویی.
4. **آینده**: ترکیب چند دارو در یک محلول، گزارش HACCP.
